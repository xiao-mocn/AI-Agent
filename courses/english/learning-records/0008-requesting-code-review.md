# 完成第 8 课：用英文请求代码评审

学习了请求代码评审时描述改动、说明关注点和礼貌请求反馈的表达，并掌握 review、PR、feedback、edge case 和 approve 等高频词。练习要求写一段三句 review 请求；练习文本框不保存内容，因此本次按推进请求记录为已完成。

**思考题回答**：
1. **Q1（ready for review）**：答案是“PR 已准备好供评审”。它表示改动已经完成到可以由同事检查的程度，不等于已经 merge 或发布。明确这个状态能让评审者知道可以开始查看。
2. **Q2（edge case）**：答案是“帮助评审者聚焦风险点”。说明你希望检查的边界情况，能让反馈更有针对性，并减少容易遗漏的异常路径。它不是为了把消息写长，而是在提前说明实现中最不确定的部分。
3. **Q3（敏感信息）**：答案是“没有敏感信息被提交”。代码评审前仍应检查 token、secret、真实配置和敏感日志，因为 reviewer 无法替代提交者的基本安全责任。发现这类信息时应先移除或替换为占位符。

**Implications**：第 9 课将学习如何回应代码评审意见，继续以 12 个新词、6 个复习词和场景练习巩固团队协作表达。
