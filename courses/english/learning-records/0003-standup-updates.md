# 完成第 3 课：站会（Standup）里的进展汇报句型

学完了站会汇报的三段式结构：用过去式说明昨天完成的工作、用 `be going to` 说明今天的计划，并在遇到障碍时用 `blocked on` 清楚地请求帮助。课程练习要求将三句话组织成一段 15–20 秒的真实进展更新；该网页文本框不保存内容，因此本次按推进请求记录为已完成。

**思考题回答**：
1. **Q1（过去式 finished）**：答案是 `finished`。`Yesterday` 给出了明确的过去时间，谓语必须使用过去式，才能让听者知道数据库迁移已经完成；`finish` 是动词原形，`finishing` 也不能独立充当谓语。在站会上，完成状态直接影响团队对进度的判断，因此时态不仅是语法问题，也是协作信息的准确性问题。
2. **Q2（be going to）**：答案是 `to`。`be going to + 动词原形` 是表达已计划事项的固定结构，所以 `start` 前必须有 `to`。站会中用这个结构能把今天的意图和昨天已完成的工作明确区分开，避免把计划误听成已完成事实。
3. **Q3（blocked on）**：答案是 `on`。`be blocked on + 具体事项` 是团队站会里报告障碍的常用搭配，后面应直接说清是什么阻塞了工作。清楚地说明 blocker 能让合适的同事及时提供帮助；若没有障碍，省略这一句即可，让站会保持简短。

**Implications**：第 4 课将学习英文技术协作中的澄清提问，在需求、术语或边界不明确时礼貌且准确地追问。
