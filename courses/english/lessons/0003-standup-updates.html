站会（Standup）里的进展汇报句型

昨天做了什么 → 今天打算做什么 → 卡在哪里需要帮助

为什么是这三句话

前两课解决了"面试时怎么介绍自己和项目"，这节课换一个场景：每天的团队站会（daily standup）。 如果团队里有英语工作语言的同事，或者你在远程/外企团队工作，站会汇报几乎是最高频、最日常的英语开口场景—— 没有面试的紧张感，但同样需要几句话把进展讲清楚。

站会汇报全球通用的结构就三句话：昨天做了什么 → 今天打算做什么 → 有没有卡住（blocker）。 这个结构比项目介绍更短、更高频，练熟了几乎每天都能用上。

三个核心句型

1说明昨天做了什么

Yesterday, I ___.

昨天，我 ___（完成的具体工作，用过去式）

Yesterday, I fixed the login bug and reviewed two pull requests.
昨天我修复了登录的 bug，还审查了两个 PR。
2说明今天打算做什么

Today, I'm going to ___.

今天，我打算 ___（计划要做的工作）

Today, I'm going to start working on the payment API.
今天我打算开始做支付 API。
3说明卡在哪里（如果没有卡住可以省略这句）

I'm blocked on ___, so I might need help with that.

我卡在 ___（具体障碍）上了，可能需要帮忙

I'm blocked on the staging environment being down, so I might need help with that.
我卡在测试环境挂了这件事上，可能需要帮忙。
三句连起来，就是一段完整的站会汇报：
"Yesterday, I fixed the login bug and reviewed two pull requests. Today, I'm going to start working on the payment API. I'm blocked on the staging environment being down, so I might need help with that."
时态提醒：第一句"昨天做了什么"必须用过去式（fixed、reviewed、finished）， 第二句"今天打算做什么"用 be going to 或 will 表示计划，两者不能混用—— 这是最容易在站会里说错的地方，也是听者判断你"到底完成没完成"的关键信号。

词汇小抄

blocked on 卡在……上——站会里报告障碍最标准的说法，比 "I have a problem with" 更简洁专业
blocker 阻碍/卡点（名词）——"Any blockers?" 是站会里主持人常问的收尾问题
pull request / PR 合并请求——开发团队日常口语里几乎都直接说 "PR"，不说全称
on track 进度正常——"We're on track to finish by Friday" 表示进度符合预期
follow up 后续跟进——"I'll follow up with him after standup" 表示会后单独沟通，不占用站会时间
