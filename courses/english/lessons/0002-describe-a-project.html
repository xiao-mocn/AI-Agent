第 2 课 · 知识 + 技能

用四句话介绍一个具体项目

项目是什么 → 你的角色 → 用了什么技术 → 遇到并解决了什么问题

为什么是这四句话

第 1 课解决了"我是谁"，这节课解决面试官紧接着的追问："能具体说说你做过的一个项目吗？" 这是技术面试里出现频率仅次于自我介绍的问题，也是站会汇报进展时最常用的表达结构。

好的项目介绍不是罗列技术名词，而是有一条叙事线：它是什么 → 我负责什么 → 我用了什么 → 我解决了什么难题。 这条线不管项目大小都适用，练熟了可以套用在任何一个项目上。

四个核心句型

1说明项目是什么

It's a / an ___ that ___.

这是一个 ___（项目类型），它 ___（做什么用的）

It's a chat backend that supports real-time AI responses.
这是一个聊天后端，支持实时 AI 回复。
2说明你的角色

My role was to ___.

我的角色是 ___（负责的具体工作）

My role was to design the API and handle authentication.
我的角色是设计 API 并处理身份验证。
3说明用了什么技术

It's built with ___.

它是用 ___（技术栈）搭建的

It's built with Node.js, Express and PostgreSQL.
它是用 Node.js、Express 和 PostgreSQL 搭建的。
4说明遇到并解决了什么问题

The biggest challenge was ___, so I ___.

最大的挑战是 ___，所以我 ___（解决办法）

The biggest challenge was handling concurrent requests, so I added a queue system.
最大的挑战是处理并发请求，所以我加了一个队列系统。
四句连起来，就是一段完整的项目介绍：
"It's a chat backend that supports real-time AI responses. My role was to design the API and handle authentication. It's built with Node.js, Express and PostgreSQL. The biggest challenge was handling concurrent requests, so I added a queue system."

词汇小抄

role 角色/职责——"my role was to..." 比 "my job was..." 更常用在项目介绍里
be built with 用……搭建的——被动语态，主语是项目本身，不是"我"
challenge 挑战/难题——比 "problem" 更常用在面试语境，听起来更积极
handle 处理/应对——"handle requests"、"handle errors" 是开发场景高频搭配
in charge of 负责……——后面接名词或动名词，如 "in charge of testing"
