# 完成第32课：测试数据清理与覆盖率

为 Vitest 配置了 `@vitest/coverage-v8` 和 `npm run test:coverage`，可以生成 V8 覆盖率报告。测试辅助函数现在记录本次随机 SQLite 数据库的精确路径，关闭 HTTP 服务和 SQLite 连接后再清理 `.db`、`-wal`、`-shm` 文件，解决了 Windows 上的 `EPERM` 文件占用错误。

**思考题回答**：
1. **Q1（精确路径）**：清理只能针对本次测试记录的精确数据库路径，不能使用 `test/*.db*` 这样的全局通配符。通配符可能误删并行测试、其他测试文件或排查保留的数据，破坏测试隔离和可追溯性。
2. **Q2（WAL/SHM）**：WAL 模式下，`-wal` 保存尚未合并的写入，`-shm` 保存协调状态。只删 `.db` 会留下不完整的测试状态和垃圾文件，本地与 CI 重跑时都可能造成混淆，因此三者必须整体清理。
3. **Q3（覆盖率取舍）**：是否补测应按风险而不是按覆盖率数字决定。鉴权、跨用户访问、错误响应和数据一致性相关分支即使很少触发也应覆盖；对日志或不可控的外部故障，可以记录风险并降低优先级。

**Implications**：第33课将把覆盖率报告接入 GitHub Actions，并为关键代码建立合理、可维护的质量门槛。
