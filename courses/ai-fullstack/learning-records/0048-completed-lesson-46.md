# 完成第 46 课：Node.js 主线复盘与上线验收清单

没有安装新依赖或修改业务代码；新增了 [Node.js 主线上线就绪评审](../../../docs/releases/nodejs-go-live-readiness.md)，用 `PASS / PARTIAL / NOT VERIFIED / BLOCKED` 复核核心行为、安全与配置、CI 与容器、部署与可观测性、数据与恢复五个领域。本地测试 9/9、TypeScript 类型检查和 8/8 候选路径盘点均通过，但评审发现 CORS、WebSocket 所有权、生产持久化配置、当前部署证据和托管数据库恢复五项高风险缺口，因此诚实结论为 `NO-GO`；文档同时提炼了 Spring Boot 迁移需要保持的 HTTP、认证、数据、健康检查、日志和测试基线。

**思考题回答**：

1. **Q1（候选证据）**：文件存在只能证明某个路径上有内容，不能证明内容正确、与当前代码一致，或已经在目标环境执行成功。CI 配置可能从未在当前提交上运行，恢复手册也可能只有步骤而没有真实恢复结果。把存在直接标为 `PASS` 会把“准备了验证工具”和“验证已经通过”混为一谈。工程上还要记录验收标准、执行结果、时间、范围和限制，才能形成可复核证据。
2. **Q2（高风险门槛）**：上线不是按检查项数量求平均分，一个认证越权、持久化缺失或恢复不可用就可能造成独立的严重事故。`NOT VERIFIED` 表示风险大小仍然未知，并不比明确失败更适合上线。即使十个低风险文档项通过，也不能抵消一个可能泄露数据的安全边界没有证据。高风险项应采用门槛规则：全部关闭并复验后才重新作出上线判断。
3. **Q3（行为契约）**：客户端、用户和运维系统依赖的是路由、状态码、JSON、认证语义、数据边界和健康检查，而不是 Node.js 的文件夹名称。Spring Boot 有 Controller、Service、Repository、Filter 和依赖注入等自己的惯用结构，照搬 Hono 组织方式会得到不自然且难维护的 Java 代码。保留外部契约并运行同一类回归测试，既能证明迁移没有改变行为，又允许新实现使用合适的框架能力。迁移还应保留预期安全语义，而不是复制本次评审发现的 CORS 和 WebSocket 缺口。

**Implications**：第 47 课将开始 Java Spring Boot 副线，建立第一个可运行项目并精确复现 Node.js `/health` 的最小外部契约。
