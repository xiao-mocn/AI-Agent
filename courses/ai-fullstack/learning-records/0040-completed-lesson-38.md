# 完成第38课：配置审计与密钥轮换

实现 JWT 立即轮换策略的回归保障：用旧密钥签发的有效格式令牌访问受保护接口时返回 401。新增无密钥轮换手册，定义 API Key 和 JWT 的更新、验证、撤销及审计记录顺序，避免凭据进入仓库或日志。配置检查、类型检查和 7 项测试均通过。

**思考题回答**：

1. **Q1（事故记录）**：旧密钥写入事故记录会让原本有限的泄露扩散到日志、工单、备份和更多人员。轮换后该记录仍可能长期存在并被再次滥用。审计应记录键名、原因、时间和结果，而不是凭据。
2. **Q2（验证新 Key）**：先验证新 Key 能避免撤销旧 Key 后服务立即失去第三方访问能力。验证成功后再撤销旧值，能够将可用性风险限定在受控发布窗口内。
3. **Q3（JWT 策略）**：立即轮换实现简单且安全窗口最短，但会强制所有用户重新登录。双密钥兼容可减少用户中断，却增加旧密钥暴露时间、实现复杂度和到期治理成本。

**Implications**：第39课将学习生产环境健康检查与可观测性边界，判断服务是否就绪，同时避免接口暴露内部依赖和敏感信息。
