# 完成第30课：给后端 API 写自动化测试

在 `ai-backend` 安装并配置了 Vitest、Supertest 和类型定义，把 `src/index.ts` 中的应用组装逻辑提取到 `src/app.ts`，使测试可以导入路由而不启动调度器、队列和 WebSocket。测试通过 `DB_PATH` 使用独立 SQLite 文件，在动态导入应用前完成初始化；DeepSeek 调用被 Mock，避免测试依赖密钥、网络或真实模型额度。

新增的会话测试覆盖了注册、登录、发送消息后列出会话，以及跨用户删除会话必须返回 404 且原会话仍存在。由于 Hono `app` 是 Fetch 应用，实际测试使用 `@hono/node-server` 创建临时 Node Server 交给 Supertest，并在测试结束后关闭它；`npm test` 已验证 2 条测试均通过。

**思考题回答**：
1. **Q1（测试数据库隔离）**：独立临时数据库让每次测试从可预测的空状态开始，不会污染开发聊天记录，也不会受已有数据影响而偶发失败。若直接使用 `chat.db`，测试注册的用户、会话和消息会混入本地数据，甚至可能误删或覆盖真实数据。测试并行运行时还会互相干扰，使结果无法复现。临时库的代价是需要在结束后清理对应的 `.db`、`-wal` 和 `-shm` 文件。
2. **Q2（应用组装与启动分离）**：直接导入 `src/index.ts` 会立即执行 `initDB().then(() => serve(...))`，同时启动端口监听、定时任务、队列和 WebSocket。测试会因此占用端口、留下运行中的句柄，可能无法自动退出，也把无关的后台副作用带进测试。拆出 `app.ts` 后，测试只获得已注册路由的应用实例，可以自行创建和关闭最小范围的临时 Server。这个边界也使路由层更容易在不依赖进程生命周期的情况下验证。
3. **Q3（越权读取的断言）**：按当前接口契约，应断言 `200` 且 `messages` 是空数组，因为接口刻意不暴露“资源不存在”和“不属于你”的差异。它保护了一部分资源存在性信息，但也更容易让测试遗漏越权边界，因为只检查状态码会误以为访问成功。测试必须进一步断言数组为空，并先用用户 A 创建带消息的会话，才能证明用户 B 没有读到数据。若未来接口改成 404，测试也应随契约改为状态码断言。

**Implications**：第31课将把本地的 `npm test` 接入 GitHub Actions，在每次 push 和 pull request 时自动执行，让权限边界测试成为合并前的基础门槛。
