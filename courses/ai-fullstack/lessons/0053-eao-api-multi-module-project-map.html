0. 先换一种看代码的方式

不要从第一行开始读仓库。大型项目不是一本从第一页读到最后一页的书，更像一座城市。你先认主干道和城区，再根据任务进入一条街。今天的四个“城区”就是三个领域模块和一个启动模块。
前端类比：Vite 工程

根目录的 package.json 能组织依赖和脚本，但真正的页面代码分散在 views、api、components。后端多模块项目也有“总控”和“业务实现”的分工。

今天必须掌握

模块名称、模块职责、启动入口、根 POM 的聚合作用，以及“需求先路由到模块”的方法。

今天只需认识

公司 Starter、Feign、Quartz、Prometheus、Docker、数据库脚本等名字。它们存在，但不进入本课主线。

今天绝不修改

eao-api 与 eao-front 都保持只读。练习结果写在本页文本框或你的笔记里。

1. 一张图看懂四个模块

点击右侧站点，查看它负责什么

eao-api/
├─ README.md          # 项目边界说明
├─ pom.xml            # 聚合四个模块
├─ domains/
│  ├─ eao-system/  # 身份与系统管理
│  ├─ eao-infra/   # 平台基础设施
│  └─ eao-model/   # 能源业务模型
├─ app/             # 组装并启动
├─ database/          # 数据库脚本
└─ files/             # 项目辅助文件
先点一个模块。

你会看到它接收哪类需求，以及现在应读到什么深度。

一句话地图：system 管“谁能做什么”，infra 管“平台靠什么运行”，model 管“能源业务是什么”，app 负责“把它们装起来并启动”。这不是绝对规则，但足够作为第一轮导航。

2. 第一步：根 pom.xml 是模块总目录

01

只读打开两个文件

路径：E:\project\eao-api\README.md 与 E:\project\eao-api\pom.xml

POM 是 Maven 的 Project Object Model，也就是构建项目时读取的 XML 配置。根 POM 中最关键的不是成百上千个依赖，而是下面这几行：

<artifactId>eao-api-parent</artifactId>
<packaging>pom</packaging>

<modules>
    <module>domains/eao-system</module>
    <module>domains/eao-infra</module>
    <module>domains/eao-model</module>
    <module>app</module>
</modules>
标签通俗解释本项目中的结论
artifactId这个 Maven 项目的名字根项目叫 eao-api-parent
packaging=pom它主要负责组织构建，不产出可运行服务包不要在根目录寻找启动类
modules参与同一次 Maven 构建的子项目目录三个领域模块加一个 app

重要区别：“父 POM”和“聚合 POM”不是同一个概念。当前根 POM 同时承接了项目继承关系并列出模块，但你今天只需掌握聚合：从根目录执行 Maven 构建时，Maven Reactor 会收集模块并根据依赖关系安排顺序。

3. 第二步：app 是组装点，也是唯一启动入口

02

沿依赖看“组装”，沿 main 看“启动”

路径：E:\project\eao-api\app\pom.xml 与 E:\project\eao-api\app\src\main\java\com\dgc\eao\api\EaoApiApplication.java

app/pom.xml 的打包方式是 jar，并依赖 eao-system、eao-infra、eao-model。这意味着业务实现被拆在三个模块中，app 再把它们组合进一个可运行应用。

@SpringBootApplication(
    scanBasePackages = {"com.dgc.eao.api", "com.dgc.ems.hmi"},
    exclude = QuartzAutoConfiguration.class
)
public class EaoApiApplication {
    public static void main(String[] args) {
        SpringApplication.run(EaoApiApplication.class, args);
    }
}
代码运行时作用现在要记住什么
@SpringBootApplication组合自动配置、组件扫描和应用配置身份这是 Spring Boot 启动类标志
scanBasePackages告诉 Spring 去哪些 Java 包查找受管理组件三个领域模块的包也会被扫描
mainJava 进程入口，调用 Spring Boot 启动应用运行服务从这里开始
exclude排除一项自动配置先知道它是显式关闭 Quartz，不追内部原因
容易误解：app 负责让业务代码“进入同一个应用”，不代表所有 Controller 和 Service 都应该写在 app。你接到品牌、设备、权限或文件需求时，第一站通常仍是对应的 domains 模块。

5. 动手：用 PowerShell 验证地图

03

只读执行三组命令

这些命令不会修改文件。每执行一组，都先预测输出，再核对。

# 1. 看根项目有哪些一级入口
Get-ChildItem 'E:\project\eao-api' -Force

# 2. 从根 POM 抽出模块与打包方式
rg -n '<packaging>|<module>' 'E:\project\eao-api\pom.xml'

# 3. 找唯一的 Spring Boot 启动调用
rg -n 'SpringApplication\.run' 'E:\project\eao-api' -g '*.java'

预期看到：根 POM 的打包方式是 pom，声明四个模块；SpringApplication.run 位于 app 的 EaoApiApplication.java。

为什么用 rg？你不需要记住所有目录。真实工作中先用 URL、类名、方法名或注解快速缩小范围，再阅读少量相关文件，比在 IDE 目录树中逐层展开更可靠。

6. 先忽略这些，不等于永远不学

看到的内容今天的处理方式什么时候再深入
公司内部 Starter只记录它提供的大致能力实际需求经过该组件时
Feign、MQ、MQTT先识别为跨服务或消息通信普通 Controller 链路稳定后
Quartz 排除配置知道 API 服务不承担定时任务学习服务职责边界时
Prometheus、Docker、CI知道属于运行与交付支撑恢复部署与运维主线时
database/、files/知道不是 Java 业务包需求明确涉及脚本或文件时
认知边界：本课的模块判断是“第一站”，不是最终结论。真实需求可能跨模块，例如删除设备前查询权限。正确做法是先进入最可能的业务模块，再沿实际调用关系扩展范围。

8. 本课总结

  • 根 pom.xml 通过 packaging=pom 和 modules 聚合四个 Maven 模块。
  • eao-system 处理身份与系统管理，eao-infra 处理平台基础设施，eao-model 处理能源业务模型。
  • app 依赖三个领域模块，提供唯一的 Spring Boot 启动入口，并扫描领域包中的组件。
  • 接到需求先判断业务模块，再用 URL、类名、方法名或注解缩小范围。
  • 本阶段先掌握普通 HTTP 业务链路，公司 Starter 和复杂中间件只识别职责。
