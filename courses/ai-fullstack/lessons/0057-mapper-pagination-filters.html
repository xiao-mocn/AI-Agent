1. Mapper 不一定对应一个 XML 文件

01

先看接口声明和父接口

真实文件：domains/eao-model/.../dal/mapper/model/brand/BrandInfoMapper.java

@DS(DataSourceEnum.MODEL)
@Mapper
public interface BrandInfoMapper extends BaseMapperX<BrandInfoDO> {
    default PageResult<BrandInfoDO> selectPage(
            BrandPageReqVO reqVO, String brand, String manufacturer) {
        return selectPage(reqVO, new LambdaQueryWrapperX<BrandInfoDO>()
                .likeIfPresent(BrandInfoDO::getBrand, brand)
                .likeIfPresent(BrandInfoDO::getManufacturer, manufacturer)
                .orderByDesc(BrandInfoDO::getCreateTime));
    }
}

@Mapper 将该接口交由 MyBatis 识别；继承 BaseMapperX<BrandInfoDO> 复用项目的通用增删改查与分页能力。这里的 default 表示接口自己提供了这段 Java 方法体，所以这一分页方法不需要另找同名 XML 来理解条件。

区分声明与执行：这个默认方法写明查询使用哪些条件并调用父接口能力；底层 SQL 如何生成、如何分页，由 MyBatis 和项目框架完成。不要把条件构造代码误认为手写 SQL。

2. 逐个读查询条件

02

字段引用让条件和 DO 属性绑定

代码读法没有筛选值时
likeIfPresent(BrandInfoDO::getBrand, brand)按品牌型号字段做模糊匹配值缺省时跳过该筛选
likeIfPresent(BrandInfoDO::getManufacturer, manufacturer)按品牌商字段做模糊匹配值缺省时跳过该筛选
orderByDesc(BrandInfoDO::getCreateTime)按创建时间倒序排列排序仍应用

BrandInfoDO::getBrand 是 Java 方法引用，用它指向 DO 字段对应的属性；Lambda wrapper 将属性与查询条件连接起来，减少手写列名。

3. 分页参数从哪里来

03

Mapper 接收 VO，所以可以把分页信息交给基础能力

selectPage(reqVO, wrapper) 的第一个参数仍是 BrandPageReqVO。它继承 PageParam，包含 pageNo 与 pageSize；Mapper 使用继承来的分页查询能力返回 PageResult<BrandInfoDO>。在本课只需要确认“分页参数在哪里、结果类型是什么”，底层拦截器和 SQL 生成放到以后。

PageResult<BrandInfoDO>
├─ list: 当前页 BrandInfoDO 列表
└─ total: 符合条件的总记录数

4. 动手验收：把条件说成人话

对着真实方法写出四点

6. 本课总结

  • BrandInfoMapper 接收分页 VO 与筛选值，构造查询条件并调用基础分页能力。
  • likeIfPresent 仅在筛选值存在时添加模糊条件；orderByDesc 固定按创建时间倒序。
  • 本项目分页查询的条件写在 Java 默认方法中，不对应一个单独的 XML 查询文件。
  • Mapper 结果是 PageResult<BrandInfoDO>，Service 再通过 BrandConvert 映射为 PageResult<BrandRespVO>。
