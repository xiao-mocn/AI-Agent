第五十六课：
追踪 Service 的分页编排

预计 60–90 分钟 · 后端上岗桥接 · 第 4 天

Controller 已经把请求交给 brandService.getBrandPage(pageReqVO)。这一行不像前端的“再调一个 API”，而是进入业务层的明确边界：接口声明承诺能力，实现类组织查询与转换。

本课胜利点

  • 能从 Controller 字段定位到 BrandService 接口。
  • 能在 BrandServiceImpl 找到同签名实现。
  • 能复述分页链路中 Mapper、DO、Convert、RespVO 的先后顺序。
  • 能解释 Service 为什么不应返回数据库 DO 给 Controller。
  • 能区分本课必须掌握的编排职责与暂不展开的 SQL 细节。

0. 先写出你的预测

不打开实现类，先回答

Controller 接到 BrandPageReqVO 后，Service 最可能把它交给哪个层？拿到数据库对象后，为什么不能直接返回给前端？带着预测再阅读，能减少“看过很多行、没有形成链路”的感觉。

前端类比：把 Service 想成页面调用 API 后的业务编排函数；它不负责 HTTP 路由，也不直接把数据库表模型泄露给页面。

1. 从 Controller 进入接口：先确认契约

01

字段类型是下一站的线索

@Resource
private BrandService brandService;

public CommonResult<PageResult<BrandRespVO>> getBrandPage(
        @RequestBody BrandPageReqVO pageReqVO) {
    return success(brandService.getBrandPage(pageReqVO));
}

先跳到 BrandService，确认接口中的方法签名：输入仍是 BrandPageReqVO，返回变成 PageResult<BrandRespVO>。接口只声明“能完成什么”，此时还没有说明怎样查库。

2. 从接口进入实现：找到真正的编排

02

用同名、同参数、同返回类型确认实现

@Override
public PageResult<BrandRespVO> getBrandPage(BrandPageReqVO pageReqVO) {
    PageResult<BrandInfoDO> pageResult = brandInfoMapper.selectPage(
            pageReqVO, pageReqVO.getBrand(), pageReqVO.getManufacturer());
    return BrandConvert.INSTANCE.convertPage(pageResult);
}

@Override 是这里的护栏：它声明这个方法实现了接口的同一项承诺。第一行从 Mapper 取回数据库对象的分页结果，第二行把它转换为对外响应 VO；这两步正是本节要能复述的业务编排。

暂不追 SQL：本课只确认 Mapper 调用的输入、输出和转换位置。筛选条件怎样拼成 SQL、分页插件如何工作，留给后续 Mapper 课；不要因一次追太深而丢掉主线。

3. 把类型变化画成一条链

01 · ControllerBrandPageReqVO
02 · MapperPageResult<BrandInfoDO>
03 · ConvertconvertPage(...)
04 · Service 返回PageResult<BrandRespVO>
BrandPageReqVO
  → brandInfoMapper.selectPage(...)
  → PageResult<BrandInfoDO>
  → BrandConvert.INSTANCE.convertPage(...)
  → PageResult<BrandRespVO>

DO 是数据访问层使用的对象，通常贴近表字段；RespVO 是接口响应使用的对象，表达允许对外输出的数据。Convert 让两种职责分开，未来新增内部字段时不会自然地泄露到接口。

4. 动手验收：用证据描述 Service 边界

只写四行，不要解释 SQL

  1. 接口文件和方法签名。
  2. 实现类和 @Override 方法。
  3. Mapper 的输入与返回类型。
  4. Convert 前后的元素类型变化。

5. 检索练习

先定职责，再定类型 · 每题只有一个正确答案

1. 为什么先查看 BrandService 接口，而不是立刻读 Mapper？

2. Mapper 返回 PageResult<BrandInfoDO> 后，Service 紧接着做什么？

3. 把 BrandInfoDO 直接返回给 Controller 的主要风险是什么？

6. 本课总结

  • BrandService 是 Controller 与业务实现之间的能力契约。
  • BrandServiceImpl#getBrandPage 编排 Mapper 查询与 Convert 转换。
  • Mapper 侧得到 PageResult<BrandInfoDO>，Convert 后才成为接口使用的 PageResult<BrandRespVO>。
  • 当前要掌握的是职责、类型和调用顺序；SQL 条件与分页实现稍后再追。
