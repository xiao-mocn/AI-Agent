第二十五课：WebSocket 实时通信

目标时长 1.5 小时 · 难度 ⭐⭐⭐ · 后端 · 实时通信

本节课你会学到：
  • 为什么轮询和 SSE 不够用，WebSocket 解决的是"服务器主动推送"这个根本问题
  • HTTP 连接怎么"升级"成 WebSocket 长连接（协议层面简单科普）
  • 用 ws 库在现有 HTTP 服务器上挂载 WebSocket 服务
  • WebSocket 握手阶段怎么做 JWT 鉴权（浏览器原生 API 不支持自定义 header 的坑）
  • 把第二十四课的后台队列和 WebSocket 打通：AI 处理完，主动推给对应用户
  • 优雅关闭时怎么处理还挂着的 WebSocket 连接

一、为什么需要 WebSocket

第十课我们用 SSE（Server-Sent Events）实现了流式输出——服务器可以持续往客户端"推"数据，但那是"一问一答"里的推：客户端发起一次请求，服务器在这次响应里边生成边发，请求结束，通道也就关了。第二十四课把 AI 调用挪到了后台队列，问题也随之而来：用户发消息后请求立刻返回"已收到"，但 AI 什么时候处理完、结果是什么，服务器要怎么"主动"告诉客户端？

这时候三种方案摆在面前：

方案原理问题
轮询（polling）客户端每隔几秒发一次 GET /status 问"好了没"大部分请求都是空跑，浪费带宽和服务器资源，还有几秒延迟
SSE客户端发起一次请求，服务器在同一个连接上持续推送只能服务器→客户端单向推，且这次请求和"提交消息"那次请求是分开的，需要额外接口配合
WebSocket一次握手后建立全双工长连接，双方随时可以发消息需要维护连接状态（谁连着、连不上怎么办），比无状态的 HTTP 复杂

这节课选 WebSocket，是因为它天然匹配"后台任务完成后主动通知"这个场景：连接建立后一直开着，队列 worker 处理完任务，随时可以往这条连接上写数据，不需要客户端反复问。

WebSocket 连接建立时会先发一个特殊的 HTTP 请求（带 Upgrade: websocket header），服务器同意后，这条 TCP 连接就从 HTTP 协议"切换"成了 WebSocket 协议，后续双方都可以随时发消息，不再有请求/响应的概念。这个过程叫"协议升级"，你不需要自己实现，ws 库会处理好。

二、WebSocket 鉴权的坑：握手阶段没有自定义 header

REST API 鉴权靠 Authorization: Bearer <token> header，第十一、十二课已经很熟悉了。但浏览器原生的 WebSocket 构造函数不支持设置自定义 header：

new WebSocket('ws://localhost:3000') // 没有地方传 Authorization header

常见的绕过办法是把 token 放进连接的 URL 查询参数里，在服务器握手阶段读出来验证：

new WebSocket(`ws://localhost:3000?token=${jwtToken}`)
查询参数会被记录在服务器访问日志、代理日志、浏览器历史记录里，存在 token 泄露风险。生产环境更稳妥的做法是：握手时只传一个一次性的短期"连接票据"（由后端在登录后单独签发、用一次就失效），而不是直接把长期 JWT 放在 URL 上。这节课为了聚焦 WebSocket 本身的机制，先用现有 JWT 演示，实际项目上线前应该替换成一次性票据。

三、把队列和 WebSocket 串起来

回顾第二十四课的流程：请求进来 → enqueue() 塞进内存队列 → 立刻返回"已收到" → worker 在后台调用 AI → 处理完。现在补上最后一环：

  1. 客户端登录后，用 JWT 建立一条 WebSocket 连接，服务器验证通过后，把这条连接和用户的 sessionId 关联起来存进一个 Map
  2. worker 处理完某个 sessionId 的任务后，从 Map 里查出对应连接，把结果 send 过去
  3. 如果这个 sessionId 当前没有活跃连接（比如用户关掉了页面），就跳过推送——这次结果仍然已经写进了数据库，用户下次打开页面刷新历史消息时能看到

四、动手实践

1安装 ws 和类型定义 
npm install ws
npm install --save-dev @types/ws
2新增 src/middleware/websocket.ts：挂载 WebSocket 服务并维护连接表 
import { WebSocketServer, WebSocket } from 'ws'
import type { Server } from 'http'
import jwt from 'jsonwebtoken'
import { JWT_SECRET } from '../config'
import { logger } from '../business/logger'

let wss: WebSocketServer | null = null
// sessionId -> 该会话当前活跃的连接
const connections = new Map<string, WebSocket>()

export function attachWebSocket(server: Server) {
  wss = new WebSocketServer({ server })

  wss.on('connection', (ws, req) => {
    const url = new URL(req.url ?? '', 'http://localhost')
    const token = url.searchParams.get('token')
    const sessionId = url.searchParams.get('sessionId')

    if (!token || !sessionId) {
      ws.close(1008, '缺少 token 或 sessionId')
      return
    }

    try {
      jwt.verify(token, JWT_SECRET)
    } catch {
      ws.close(1008, 'token 无效或已过期')
      return
    }

    connections.set(sessionId, ws)
    logger.info({ sessionId }, 'WebSocket 连接已建立')

    ws.on('close', () => {
      // 只清掉仍然指向这条连接的记录，避免新连接被旧的 close 事件顶掉
      if (connections.get(sessionId) === ws) {
        connections.delete(sessionId)
      }
      logger.info({ sessionId }, 'WebSocket 连接已关闭')
    })
  })
}

// worker 处理完任务后调用，把结果推给对应会话；没有活跃连接就静默跳过
export function pushToSession(sessionId: string, payload: unknown) {
  const ws = connections.get(sessionId)
  if (ws && ws.readyState === WebSocket.OPEN) {
    ws.send(JSON.stringify(payload))
  }
}

// 优雅关闭时调用，主动断开所有客户端并停掉 WebSocketServer
export function closeWebSocket() {
  for (const ws of connections.values()) {
    ws.close(1001, '服务器正在重启')
  }
  connections.clear()
  wss?.close()
}
ws.close(1008, '...') 里的 1008 是 WebSocket 协议的标准关闭码，表示"策略违规"（这里指鉴权失败）；1001 表示"端点正在离开"（这里指服务器关闭）。客户端可以根据这个码判断是要重连还是提示用户重新登录，不用去解析错误文本。
3在 src/middleware/queue.ts 里，任务处理完就推送结果 
import { pushToSession } from './websocket'

async function processTask(task: Task) {
  logger.info({ taskId: task.id }, '开始处理任务')
  // const reply = await callAIAndSave(task.sessionId, task.content)
  pushToSession(String(task.sessionId), {
    type: 'ai-reply-done',
    taskId: task.id,
    // reply,
  })
}
4在 src/index.ts 里接入启动与优雅关闭 
import { attachWebSocket, closeWebSocket } from './middleware/websocket'

// 启动时，server 建好之后立刻挂载
const server = serve({ fetch: app.fetch, port: PORT }, (info) => {
  logger.info(`服务器已启动：http://localhost:${info.port}`)
  startScheduler()
  startWorker()
})
attachWebSocket(server)

// 优雅关闭时，在等 worker 跑完、停调度器之后，再关 WebSocket 连接
server.close(async () => {
  await waitForWorker()
  stopScheduler()
  closeWebSocket()
  // ...关数据库、process.exit(0)
})

五、本课总结

  • 轮询浪费资源、SSE 只能单向推且绑定在一次请求上，WebSocket 是"服务器随时主动推送"场景的正解
  • 浏览器原生 WebSocket API 不支持自定义 header，鉴权 token 常见做法是放进连接 URL 的查询参数，生产环境应该用一次性票据代替长期 JWT
  • ws 库可以直接挂在现有 HTTP server 上，不需要单独起一个端口
  • 用 Map<sessionId, WebSocket> 维护连接表，是"后台任务完成后精准推给某个用户"的核心数据结构
  • 优雅关闭时要主动关闭所有 WebSocket 连接，并且要排在 worker 处理完、调度器停止之后
