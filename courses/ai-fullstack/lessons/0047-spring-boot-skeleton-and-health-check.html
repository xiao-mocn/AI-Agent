第四十七课：Spring Boot 项目骨架与健康检查

目标时长 1 小时 · 难度 ★★☆ · Java 副线 · 第一个 Spring Web 契约

本课你会学到：
  • 用 Spring Initializr 建立独立的 Java 21 + Maven Wrapper 项目。
  • 理解 Spring Boot 启动类、Controller、注解路由与依赖管理的职责。
  • 用 MockMvc 锁定与 Node.js 一致的 /health 外部契约。
  • 启动 Spring Boot 服务，并用 PowerShell 验证真实 HTTP 响应。

一、迁移从最小外部契约开始

第 46 课已经定义 Java 迁移原则：客户端依赖路由、状态码和 JSON，不依赖 Hono 的文件结构。因此第一步不是搬运全部业务代码，而是让一个全新的 Spring Boot 服务精确回答 GET /health，并用自动化测试证明它与 Node.js 契约一致。

这个切片足够小，却覆盖了 Java 副线最重要的基础：JDK、Maven 项目、Spring Boot 启动、注解路由、JSON 序列化和 Web 层测试。一旦这些环节跑通，后续认证、数据库和 AI 调用都可以沿用“先定义外部行为，再选择 Java 内部结构”的方式迁移。

主阅读资源：Spring Boot 官方参考文档。本课只使用 Spring Web 和测试依赖，不引入数据库、Spring Security 或 AI SDK。

@RestController 告诉 Spring：这个类处理 Web 请求，返回值直接写入响应体。@GetMapping 声明一个 GET 路由。Spring 会自动发现启动类所在包及其子包中的组件，因此 Controller 应放在 com.example.ai 的子包下。

三、版本与构建工具边界

本机当前有 JDK 23，可以编译目标为 Java 21 的项目；课程选择 Java 21 是因为它是长期支持版本，也更接近企业项目常见基线。全局没有 Maven 不构成阻塞，Spring Initializr 会生成 mvnw.cmd，它把项目需要的 Maven 版本固定在仓库中。

第一次运行 Maven Wrapper 需要从 Maven Central 下载依赖，必须有网络。不要从不明脚本安装 JDK 或 Maven；如果 java -version 不可用或低于 21，先通过受信任的发行版安装 JDK 21，再继续本课。
新项目必须放在仓库根目录的 java-backend/，不要覆盖 ai-backend/。不要复制 Node.js 的 .env、数据库、JWT 密钥或 API Key；本课的健康检查不读取任何依赖或敏感配置。

四、动手实践

1检查环境并生成项目

从仓库根目录运行环境检查。当前机器应显示 Java 23；没有全局 Maven 是预期状态。

java -version
if (Get-Command mvn -ErrorAction SilentlyContinue) { mvn -version } else { '使用项目自带 Maven Wrapper' }

打开 Spring Initializr，选择 Maven、Java、Spring Boot 3.5.x 最新维护版、Group com.example.ai、Artifact java-backend、Packaging Jar、Java 21，只添加 Spring Web。本课测试代码按 Spring Boot 3.5 的包名编写，不要切换到 4.x。下载后先确认仓库根目录不存在同名目录，再将压缩包解压为 java-backend/。生成结果必须包含 pom.xml、mvnw.cmd 和 src/。

2实现最小 HealthController

新建 java-backend/src/main/java/com/example/ai/health/HealthController.java。返回不可变 Map，让 Jackson 自动生成与 Node.js 相同的 JSON。

package com.example.ai.health;

import java.util.Map;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HealthController {
    @GetMapping("/health")
    public Map<String, String> health() {
        return Map.of("status", "ok");
    }
}
3用 MockMvc 锁定外部契约

新建 java-backend/src/test/java/com/example/ai/health/HealthControllerTest.java。测试不启动真实端口，也不加载数据库，只验证 Web 层必须保持的三个条件：状态码 200、JSON 内容类型、status=ok。

package com.example.ai.health;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@WebMvcTest(HealthController.class)
class HealthControllerTest {
    @Autowired
    private MockMvc mvc;

    @Test
    void healthMatchesNodeContract() throws Exception {
        mvc.perform(get("/health"))
            .andExpect(status().isOk())
            .andExpect(content().contentTypeCompatibleWith(MediaType.APPLICATION_JSON))
            .andExpect(jsonPath("$.status").value("ok"));
    }
}

在 java-backend 目录运行 .\mvnw.cmd test。成功标准是构建为 BUILD SUCCESS，且 HealthControllerTest 通过。

4启动服务并对照真实响应

在第一个 PowerShell 窗口从 java-backend 运行 .\mvnw.cmd spring-boot:run。看到应用监听 8080 后，在第二个窗口执行下面命令；不要为了同时运行 Node 服务而改动本课契约。

$response = Invoke-RestMethod -Uri 'http://localhost:8080/health'
$response | ConvertTo-Json -Compress
if ($response.status -ne 'ok') { throw 'health contract mismatch' }

输出必须是 {"status":"ok"}。验证完成后回到第一个窗口按 Ctrl+C 停止服务，并确认没有连接数据库或读取敏感配置。

五、验收清单

  1. java -version 为 21 或更高，项目目标版本为 Java 21。
  2. java-backend/ 独立存在，包含 pom.xml、mvnw.cmd 和 Spring Web 依赖，没有覆盖 Node 项目。
  3. HealthController 只返回存活状态，不查询数据库、环境变量或外部服务。
  4. HealthControllerTest 同时断言 200、JSON 内容类型和 status=ok，Maven 测试通过。
  5. 真实 HTTP 请求返回 {"status":"ok"}，验证后服务已停止。
  6. 没有复制、读取或提交 Node.js 的密钥、数据库和环境配置。

六、本课总结

  • Java 副线从一个可运行、可测试、可对照的外部契约开始。
  • Spring Boot 用启动类管理应用，用 Controller 与映射注解表达 HTTP 路由。
  • Maven Wrapper 固定构建工具版本，不要求机器预装全局 Maven。
  • MockMvc 提供与 Supertest 相似的契约测试能力，迁移结果由行为而非目录判断。
  • /health 只证明进程存活，数据库就绪应由独立的 /ready 负责。
