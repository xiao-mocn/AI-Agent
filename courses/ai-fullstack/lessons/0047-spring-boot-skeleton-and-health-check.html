第四十七课：Spring Boot 4 项目骨架与健康契约

目标时长 60 分钟 · Java 副线起点 · Spring Boot 4.1.1 · Java 21

不搬业务代码，也不急着接数据库。先让一个全新的 Java 服务对外说出与 Node.js 一样的第一句话，并用测试证明它没有说错。

本课胜利点

  • 建立一个独立的 Java 21 + Maven Wrapper + Spring Boot 4.1.1 项目。
  • 用 Controller 和 Java record 实现一个稳定的 JSON 外部契约。
  • 先写 @WebMvcTest，再实现 GET /health。
  • 分别取得“测试通过”和“真实 HTTP 响应”两类证据。

1. 迁移先保住外部行为

第 46 课的上线评审指出：客户端和运维系统依赖的是路径、状态码、JSON 和安全语义，不是 Hono 的目录结构。Java 可以采用 Spring 的惯用组织方式，但必须先把最小外部行为锁住。

GET /health→HTTP 200→{"status":"ok"}

这里的 /health 只回答“这个 Java 进程是否已成功启动并能处理最小 HTTP 请求”。它不检查数据库、缓存、LLM、网络或任何密钥；把外部依赖塞进存活检查，可能在外部系统短暂故障时触发无意义的重启。

本课边界：不迁移登录、数据库、AI 对话或 Node.js 配置。请勿复制 .env、数据库文件、JWT 密钥或 API Key。

2. 当前技术基线

Spring Boot 4.1.1 至少需要 Java 17；本课选 Java 21，既满足版本要求，也适合作为长期维护项目的明确基线。用 Maven Wrapper 固定构建入口，因此机器不必预装全局 Maven。

4. 分层实践：先测试，后实现

1

生成项目与确认环境

在 Spring Initializr 按上表生成项目，解压到 java-backend/。然后执行：

java -version
Set-Location java-backend
.\mvnw.cmd --version

记录 Java 版本与 Maven Wrapper 版本。第一次运行会下载受信任仓库中的构建依赖，因此需要网络；不要运行来源不明的安装脚本。

2

先写 Web 层契约测试

创建 src/test/java/com/example/ai/health/HealthControllerTest.java。Spring Boot 4 的 @WebMvcTest 位于 Web MVC 测试包；它会配置 MVC 基础设施和 MockMvc，但不启动真实端口。

package com.example.ai.health;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.webmvc.test.autoconfigure.WebMvcTest;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@WebMvcTest(HealthController.class)
class HealthControllerTest {
    @Autowired
    MockMvc mvc;

    @Test
    void healthMatchesContract() throws Exception {
        mvc.perform(get("/health"))
           .andExpect(status().isOk())
           .andExpect(content().contentTypeCompatibleWith(MediaType.APPLICATION_JSON))
           .andExpect(jsonPath("$.status").value("ok"));
    }
}

现在运行 .\mvnw.cmd test。在 Controller 尚未存在时，失败是预期证据：你已经先把行为写成了可执行的要求。

3

用最小实现让测试通过

在 src/main/java/com/example/ai/health/ 下创建响应 record 与 Controller。record 把响应字段写成类型，而不是散落的字符串键。

package com.example.ai.health;

public record HealthResponse(String status) { }
package com.example.ai.health;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
class HealthController {
    @GetMapping("/health")
    HealthResponse health() {
        return new HealthResponse("ok");
    }
}

再次执行 .\mvnw.cmd test。这次只有状态码、JSON 内容类型和 status 都满足契约时，测试才会通过。

4

补一条真实 HTTP 证据

MockMvc 快速验证 MVC 层；但它不等于完整的嵌入式服务器验证。另开一个 PowerShell 窗口运行应用，再请求真实端口：

.\mvnw.cmd spring-boot:run
$response = Invoke-RestMethod -Uri 'http://localhost:8080/health'
$response | ConvertTo-Json -Compress
if ($response.status -ne 'ok') { throw 'health contract mismatch' }

预期输出包含 {"status":"ok"}。验证后回到运行窗口按 Ctrl + C 停止服务。

5. 验收与变式练习

交付前逐项确认

  • java-backend/ 独立存在，且没有覆盖 Node.js 项目。
  • 测试先失败、实现后 .\mvnw.cmd test 通过。
  • GET /health 返回 200、JSON 和 status=ok。
  • 真实端口验证后，应用进程已停止。
  • 没有读取、复制或提交任何密钥与生产数据。

变式练习：脱稿再做一次

关闭上面的代码块，新增 GET /version，让它返回固定 JSON {"version":"0.1.0"}。先为它写状态码、内容类型和 JSON 字段三条断言，再实现 Controller 方法。此练习只在你的本地 Java 项目中完成；不要提交到现有业务项目。
