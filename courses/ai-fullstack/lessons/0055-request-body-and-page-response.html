读懂请求体与分页响应

预计 60–90 分钟 · 后端上岗桥接 · 第 3 天

上一课你已经找到了 HTTP 入口。现在把镜头推进方法签名：前端的筛选条件如何进入 BrandPageReqVO，而后端的分页结果又为何能被页面直接读成 list 与 total？

本课胜利点

  • 能从 @RequestBody BrandPageReqVO 解释 JSON 请求体的接收位置。
  • 能区分继承得到的分页字段与品牌模块自己的筛选字段。
  • 能读出 CommonResult<PageResult<BrandRespVO>> 的三层响应结构。
  • 能把前端的 searchParams、res.list、res.total 对上后端类型。
  • 能标出本课边界：只读 VO 和包装结构，不追 Service、Mapper 或数据库。

0. 先把第 54 课的入口接上

已确认的 Controller 方法

@PostMapping("/page")
public CommonResult<PageResult<BrandRespVO>> getBrandPage(
        @RequestBody BrandPageReqVO pageReqVO) {
    return success(brandService.getBrandPage(pageReqVO));
}

把它按前端熟悉的函数签名来读：BrandPageReqVO 是输入，CommonResult<...> 是统一信封，信封里的 PageResult<BrandRespVO> 才是分页业务数据。

本课的关键切换：上节课用“路径 + HTTP 方法”定位方法；本节课用“参数类型 + 返回类型”定位数据契约。Controller 不是业务细节的终点，但它是数据进入与离开 Java 的边界。

1. @RequestBody：把 JSON 放进参数对象

01

从前端 data 找到 Java 参数

前端：src/api/iot/brand/index.ts

getBrandPage: async (data: any) => {
  return await request.post({ url: '/model/brand/page', data })
}

data 会作为 POST 请求体发送。Controller 中的 @RequestBody 让 Spring 将这段 JSON 反序列化为 BrandPageReqVO pageReqVO；它不是“某个字段”，而是整个请求体的接收口。

边界提醒：不要把 @RequestBody 理解成自动证明输入一定合法。真实项目的校验触发时机还取决于 Controller 参数上的校验注解和全局配置；本课先确认字段归属，不擅自推断校验结果。

2. 请求 VO：分页公共字段 + 业务筛选字段

02

读继承关系，别只看当前文件

文件：eao-common/contracts/eao-model-contract/.../BrandPageReqVO.java

@Data
@EqualsAndHashCode(callSuper = true)
public class BrandPageReqVO extends PageParam {
    private String brand;
    private String manufacturer;
}

brand 与 manufacturer 是品牌模块新增的筛选条件。extends PageParam 表示 pageNo、pageSize 定义在父类，仍是这个请求对象的一部分。

字段来源字段在当前链路中的意义
PageParampageNo、pageSize告诉后端需要第几页、每页多少条；默认 1 和 10，且定义了 1–100 的边界。
BrandPageReqVObrand型号编码的模糊筛选条件。
BrandPageReqVOmanufacturer品牌商的模糊筛选条件。

3. 响应类型：从 Java 泛型还原前端对象

由外到内拆开，不要一次背下三层尖括号

01 · HTTP 响应{ code, data, msg }
02 · CommonResult统一结果信封
03 · PageResult{ list, total }
04 · BrandRespVO每一行品牌数据
CommonResult<PageResult<BrandRespVO>>
└─ data: PageResult<BrandRespVO>
   ├─ list: List<BrandRespVO>
   └─ total: Long

前端的 res.list 与 res.total 正对应 PageResult。每个 list 元素是一个 BrandRespVO，包含 brandId、brand、manufacturer、createTime 等展示字段。

7. 本课总结

  • @RequestBody BrandPageReqVO 是分页筛选 JSON 进入 Java 的位置。
  • BrandPageReqVO 自己定义 brand、manufacturer，并从 PageParam 继承 pageNo、pageSize。
  • CommonResult 是统一信封，PageResult 提供 list 与 total，BrandRespVO 描述每一条数据。
  • 现在你可以从页面字段一路解释到 Controller 参数和返回结构，而不是只知道“接口能调用”。
