1. 请求定位需要三个坐标

坐标一：HTTP 方法

GET、POST、PUT、DELETE 不是装饰。同一路径理论上可以按不同方法映射到不同处理函数。

坐标二：URL 路径

前端看到完整路径；后端常把公共前缀放在类上，把具体动作放在方法上。

坐标三：Controller 方法

找到注解还不够，要记录 Java 类名、方法名和参数类型，形成可复查证据。

暂时不追踪

Service、Mapper、VO 内部字段留给后续课程。本课只确保你找对 HTTP 入口。

点击信号节点，查看每一步留下的证据

2. 第一步：从页面找到前端 API

01

先看调用者，再看请求封装

页面：E:\project\eao-front\src\views\resource\brand\index.vue

function handleQuery() {
  loading.value = true
  BrandApi.getBrandPage({
    ...searchParams,
  }).then((res) => {
    tableData.value = res.list || []
    total.value = res.total || 0
  }).finally(() => {
    loading.value = false
  })
}

这段代码给出三个业务线索：动作是“查询”，入参来自 searchParams，返回值有 list 和 total。它还没有告诉你真实 URL，所以继续进入 BrandApi.getBrandPage。

API：E:\project\eao-front\src\api\iot\brand\index.ts

getBrandPage: async (data: any) => {
  return await request.post({
    url: `/model/brand/page`,
    data
  })
}
定位卡片：HTTP 方法是 POST，URL 是 /model/brand/page，数据通过请求体发送。先把这三项写下，再打开后端仓库。

3. 第二步：完整 URL 搜不到，不代表没有接口

02

先做一次“预期失败”的搜索

在 PowerShell 中执行，只读，不修改公司代码。

rg -n '/model/brand/page' `
  'E:\project\eao-api' `
  -g '*.java'

预期结果：没有匹配。原因不是接口不存在，而是 Java 代码里没有完整的 /model/brand/page 字符串。

@RequestMapping
"/model/brand"
+
@PostMapping
"/page"
=
POST
/model/brand/page

Spring MVC 允许在类级别声明共享映射，再由方法级注解缩小到具体端点。@PostMapping 是指定 HTTP 方法的快捷注解，所以路径与请求方法必须一起核对。

关键习惯：搜索无结果也是证据，但只说明“这个字符串没有原样出现”。不要据此断言接口不存在。先拆 URL，再搜索最稳定的业务前缀。

4. 第三步：先命中类，再确认方法

03

搜索类级前缀

rg -n '/model/brand' `
  'E:\project\eao-api' `
  -g '*.java'

预期命中：

BrandController.java:33:@RequestMapping("/model/brand")

文件：E:\project\eao-api\domains\eao-model\src\main\java\com\dgc\ems\hmi\model\controller\admin\brand\BrandController.java

@RestController
@RequestMapping("/model/brand")
public class BrandController {

    @PostMapping("/page")
    public CommonResult<PageResult<BrandRespVO>> getBrandPage(
            @RequestBody BrandPageReqVO pageReqVO) {
        return success(brandService.getBrandPage(pageReqVO));
    }
}
证据它证明什么它暂时不证明什么
@RestController这个类是返回响应体的 Web Controller不证明具体 URL
@RequestMapping("/model/brand")类内端点共享路径前缀不证明具体 HTTP 方法
@PostMapping("/page")该方法接收 POST，并补上路径后缀不解释请求体字段
getBrandPage(...)Java 入口方法及参数、返回类型不证明 Service 如何查询

6. 同一个 Controller 中的端点坐标

前端函数HTTP 坐标后端方法注解
createBrandPOST /model/brand/create@PostMapping("/create")
updateBrandPUT /model/brand/update@PutMapping("/update")
deleteBrandDELETE /model/brand/delete@DeleteMapping("/delete")
getBrandGET /model/brand/get@GetMapping("/get")
getBrandPagePOST /model/brand/page@PostMapping("/page")
方法名不是 URL。前端函数和后端方法恰好都叫 getBrandPage，但这只是项目命名习惯。Spring 真正用来匹配请求的是映射注解中的路径、HTTP 方法以及其他约束。

9. 本课总结

  • 从页面的 handleQuery 找到 BrandApi.getBrandPage，得到 POST /model/brand/page。
  • 完整 URL 在后端被拆为类级 @RequestMapping("/model/brand") 与方法级 @PostMapping("/page")。
  • 搜索完整 URL 无结果不代表接口不存在；拆路径后搜索稳定前缀。
  • 确认入口必须同时核对 HTTP 方法、组合路径、Controller 类和 Java 方法。
  • 当前入口是 BrandController#getBrandPage，请求体类型是 BrandPageReqVO。
