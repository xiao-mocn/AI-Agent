# 第 40 课：部署后烟雾测试与回滚判定

## 目标

让学习者能够在部署 Node.js AI 后端后，使用一套短小、可重复且无副作用的检查流程，判断发布是否可以继续，并在失败时及时停止和回滚。

## 教学范围

- 以 Render 为部署平台示例，给出可迁移到其他 PaaS 的通用清单。
- 将验收分为三层：存活检查、就绪检查和最小业务请求。
- 通过状态码、固定响应和无副作用请求定义继续发布、停止发布与回滚的判定条件。
- 使用 PowerShell `Invoke-WebRequest` 演示健康探针验证，不调用 DeepSeek，不发送聊天消息，不写入业务数据。

## 非范围

- 不修改现有后端代码、环境变量、数据库或 Render 项目配置。
- 不设计自动化灰度发布、流量分片或 Kubernetes 发布策略。
- 不在课程中包含真实 URL、令牌、密钥或数据库连接信息。

## 课程结构

页面沿用第 39 节的单页 HTML 样式，包含学习目标、分节说明、四步动手实践、验收清单、总结、三道思考题与下一课预告。

1. 解释烟雾测试是发布验收的最小信号，不是完整回归测试。
2. 用表格说明 `/health`、`/ready` 和无副作用业务请求分别验证的边界。
3. 提供 Render 发布后的观察窗口和 PowerShell 检查示例。
4. 定义明确的继续、停止和回滚条件，强调保留受控日志进行故障判断。
5. 链接 Render 官方部署文档作为主阅读资源，并在相关段落中给出引用。
