# AI 全栈第 48 课：后端零基础版重写设计

## 目标

在不改变第 48 课主题的前提下，将“运行时配置与就绪检查”重写为一节可独立完成的后端零基础课程。学完后，学习者能够解释：配置文件为什么存在、Spring Boot 怎样把配置交给 Java 代码、缺少关键配置为什么应在启动时失败，以及“进程活着”和“可以接收流量”的区别。

## 范围

保留以下原有教学成果：

- 用 `@ConfigurationProperties` 将 `application.properties` 中的配置绑定为 Java 类型。
- 用 `@Validated` 和 `@NotBlank` 拒绝缺少关键配置的启动。
- 添加 Actuator，并验证 readiness 健康端点及主端口的 `/readyz` 路径。
- 区分 liveness、readiness 和外部依赖检查的边界。

不引入数据库、LLM、密钥管理、部署平台配置或 Service 层；这些内容会在后续课程分别学习。

## 课程结构

1. **从真实问题开始**：通过“服务启动了但发布标签为空”的例子，建立配置错误应尽早暴露的直觉。
2. **配置的最小模型**：解释 `application.properties`、键、值、Spring Boot 启动读取配置的过程，并将其类比为前端环境变量在构建或运行时被读取。
3. **依赖与目录定位**：说明 `pom.xml` 的依赖作用、`config` 包的职责以及新增依赖的必要性。
4. **逐行构建类型化配置**：创建 `AppProperties` record；分别解释 package、import、record、字段、`@ConfigurationProperties`、`@Validated`、`@NotBlank` 和 `prefix`。每个关键元素注明省略后的后果。
5. **让 Spring 发现配置类**：修改启动类添加 `@ConfigurationPropertiesScan`，解释扫描范围和启动类位于根包的原因。
6. **写配置并做双重验证**：先以正常配置启动，再使用命令行参数临时覆盖为空值，观察并解读启动失败；明确该命令不修改配置文件。
7. **引入 Actuator 与就绪状态**：解释 Actuator 是什么、它和自定义 `/health` 的区别；添加配置并验证 `/actuator/health/readiness` 与 `/readyz`。
8. **解释状态语义**：用“重启”与“停止分流”两个平台动作区分 liveness 与 readiness；说明为什么当前不把数据库或 LLM 放入检查。
9. **巩固与排错**：给出验收清单、常见错误对照、复述题和一个不涉及敏感信息的小变式练习。

## 呈现与交互原则

- 新术语首次出现时，按“它是什么 → 为什么需要 → 写在哪里 → 不这样做会怎样”的顺序解释。
- 每个实际操作均列出目标文件、完整或足够上下文的代码、PowerShell 命令、预期现象和验证目的。
- 代码块之后增加简短的逐行解释；不把长段注释混入可复制代码。
- 明确标记“本课必须掌握”和“当前只需知道”，控制工作记忆负担。
- 练习先让学习者写出判断，再提供即时反馈；结束题检验原因与数据流，而非只检验术语记忆。

## 验收标准

- HTML 页面可正常打开，含有效的中文零基础解释、可复制命令、交互练习与官方资料链接。
- 不删除原课程主题或原有验证目标。
- 对所有首次出现的 Java/Spring 后端概念给出作用和省略后果。
- 不要求学习者提交真实密钥，也不在示例中加入敏感配置。
- 页面不包含未完成标记、前后矛盾的命令或不符合当前项目包名的路径。

## 风险与处理

课程变长可能导致阅读疲劳。通过“每次只改一个文件、每步立即验证”和“必须掌握/暂时知道”的分层来控制负担，而不是删去必要解释。Actuator 相关行为以 Spring Boot 官方文档链接为准；课程中只使用本项目已验证的 Maven 与 PowerShell 工作流。
