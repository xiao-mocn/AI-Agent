# 第 43 课：备份自动化与保留策略设计

## 目标

生成一节独立、可快速完成的 HTML 课程，帮助学习者把第 42 课的单次恢复演练延伸为可重复执行的备份流程。课程通过临时 SQLite 虚构数据演示备份命名、保留数量和恢复验证的关系，不实现或宣称实现 Render 线上数据库备份。

## 范围与边界

- 课程文件为 `courses/ai-fullstack/lessons/0043-backup-automation-and-retention-policy.html`。
- 实践命令只在系统临时目录创建其自己的目录、SQLite 文件和备份副本；验证后仅删除该目录。
- 演练数据固定为虚构记录，不读取、复制、修改或删除 `ai-backend/chat.db`。
- 不连接 Render、线上服务或任何托管数据库，不读取环境变量、凭据或真实业务数据。
- 不在仓库中新增可被误用于生产的定时任务、备份脚本或部署配置。

## 课程结构

1. **学习目标**：区分备份频率、命名规则、保留数量、RPO 与恢复验证，并能解释自动化任务和备份策略之间的差别。
2. **理论部分**：说明带时间戳的命名如何支持排序与审计；保留策略如何限制存储增长；RPO 如何约束备份间隔；为什么必须验证可恢复性而不是仅检查文件数量。
3. **实践演练**：一条 Node 命令在临时目录中创建虚构 SQLite 源库，复制出四份按固定时间序列命名的备份，按排序保留最新两份，恢复其中最新副本并以只读查询验证 `id=1`、`label=backup-retention-drill`。命令会显式断言保留结果，最后清理自身创建的临时目录。
4. **证据记录**：课程指导在 `docs/recovery/` 新增不含临时绝对路径、凭据或业务数据的演练记录，写明预期保留数量、实际保留标识、恢复查询结果、未触碰的系统和限制。
5. **检验与思考**：包含至少三项验收清单和 Q1 至 Q3，覆盖“时间戳不是调度器”“保留规则不能替代恢复验证”“本地演练不能证明托管数据库具备备份能力”。
6. **后续衔接**：最后一段预告第 44 课“备份失败可见性与恢复运行手册”。

## 数据流与安全性

`临时源库 -> 四个备份副本 -> 按文件名排序 -> 保留最新两个 -> 从保留副本恢复 -> 只读查询断言 -> 清理临时根目录`

演练中的删除仅以 `fs.rmSync` 作用于 `fs.mkdtempSync` 返回的临时根目录；不会根据用户路径、项目路径或通配符删除文件。备份名称使用固定的模拟时间序列，以确保演练可重复且不依赖系统时钟的恰好顺序。

## 验收标准

- 页面沿用现有课程 HTML 的样式、简体中文结构、`goal`、`step`、`quiz` 和末尾预告。
- 页面包含可运行的临时演练命令、边界说明、主阅读资源、总结和三道思考题。
- 命令的成功标准是仅余两份备份且恢复副本能查询到预期虚构记录，而非只看到备份文件存在。
- 新增演练记录如在生成课程时实际执行演练，则与课程的模拟数据和限制一致。
- 不修改 `ai-backend` 运行时代码、数据库、Render 配置或无关的未提交文件。
