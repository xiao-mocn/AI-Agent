# Power EMS 课程设计

## 目标

为一名负责 EMS 前端开发、目前以微电网业务为主且缺少电力行业基础的开发者，建立足以支持需求澄清、页面设计和异常处理判断的业务模型。课程不以培养电力系统设计人员为目标，而是让学习成果直接服务于前端工作。

## 学习者与约束

- 学习者目前主要接触微电网 EMS，未来可能参与换电站业务。
- 每天可稳定学习 30 分钟。
- 已具备前端开发经验，但自述对电力行业没有基础。
- 学习内容优先解释“数据和状态为何存在、何时可信、哪些操作受限”，不推导超出前端协作需要的电力公式。

## 课程范围

第一阶段只覆盖微电网 EMS，按实际页面和运行场景组织：

1. 读懂监控页：光伏、储能、负荷、电网和可选备用电源的角色；功率、能量和 SOC 的区别。
2. 读懂状态：并网、离网、待机、充电、放电、限功率与故障状态的页面含义。
3. 读懂调度：削峰填谷、需量控制、分时电价和 SOC 边界如何影响 EMS 指令。
4. 读懂风险：告警分级、测点时效、通信中断、控制确认、权限和审计。
5. 进行前端走查：将每个字段、图表和操作映射到数据来源、单位、正常范围、异常表现和业务后果。

换电站不在第一阶段讲授；完成微电网核心模型后，课程将以电池库存、充电功率、站内负荷和订单约束为映射关系进入第二阶段。

## 单课结构

每节课为一个可离线打开的 HTML 文件，预计 20 分钟学习、10 分钟练习：

1. 用一个真实的 EMS 页面问题引入概念。
2. 只讲解决该问题必需的知识，并注明权威来源。
3. 提供能量流或状态关系图，将设备、数据和操作串联。
4. 用一个可即时反馈的检索题或情景题验证理解。
5. 将可复用术语压缩到参考资料中，避免后续反复解释。

题目以真实前端判断为目标，例如判断“储能功率为负”究竟表示何种约定，或识别 SOC 已达到边界时控制按钮应呈现的状态。每个选择题的选项保持同等信息量，避免通过格式泄露答案。

## 文件与状态

课程将在 `courses/power-ems/` 内维护，和现有课程隔离：

- `MISSION.md`：业务目标、可观察的成功标准和学习边界。
- `RESOURCES.md`：经筛选的标准、官方资料和高质量社区，并标明使用场景。
- `NOTES.md`：记录每天 30 分钟、微电网优先、换电站后置等偏好。
- `reference/`：术语表、指标速查表、能量流与状态图。
- `lessons/`：编号递增的独立 HTML 课程。
- `learning-records/`：仅在学习者表现出理解、披露已有经验或纠正误解后记录，不把上课本身当成掌握。

第一节名称为“读懂 EMS 监控页的功率、能量、SOC 与运行状态”。它将建立全课程共用的符号和语义边界，并连接到术语表。

## 质量与验证

- 每个业务断言都要引用 `RESOURCES.md` 中的来源；无法可靠核实的厂商差异会显式标为“需按项目约定确认”。
- HTML 课程应可在本地直接打开，交互无需后端、外网或构建步骤。
- 每节完成前，检查链接、题目反馈和小屏幕文字布局；课程内容以本地结构检查和浏览器静态验证为准。
- 任何涉及控制指令的内容必须说明：不同项目的符号约定、保护策略和权限规则可能不同，不能把通用讲解当作现场操作指令。

## 非目标

- 不讲输配电网设计、继电保护整定或现场电气安全操作。
- 不替代项目需求文档、设备说明书、调度策略或现场运维审批。
- 不在第一阶段引入换电站的订单运营和电池资产管理细节。
