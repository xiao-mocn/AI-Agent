# 第38课设计：立即 JWT 密钥轮换

## 目标

将 JWT 密钥轮换定义为立即失效策略：部署平台替换 `JWT_SECRET` 并重启服务后，只信任新密钥签发的令牌。旧令牌必须返回 `401`，不保留旧密钥兼容窗口。

## 范围

- 保持现有单一 `JWT_SECRET` 配置，不新增旧密钥或 `kid` 支持。
- 为受保护接口补充回归测试：使用非当前密钥签发、格式正确的 JWT 必须被拒绝。
- 新增无密钥的轮换运行手册，记录操作顺序、验证项和审计字段。

## 设计

认证中间件继续用 `config.JWT_SECRET` 验证令牌，登录接口继续用同一密钥签发令牌。测试使用独立的错误密钥生成 JWT，调用 `/api/sessions` 并断言 `401`；测试不记录真实或测试环境的当前密钥值。运行手册要求先在部署平台设置新值，再执行配置检查、部署重启、验证新登录，最后撤销旧值并记录时间、原因、验证结果和负责人。

## 不做的事

- 不保存旧密钥，不实现双密钥验证或过渡期。
- 不把凭据、完整哈希、截图或供应商控制台信息写入仓库和日志。
- 不引入持久化审计系统；本课只提供安全的人工记录模板。

## 验证

1. 新增的错误签名 JWT 回归测试通过。
2. 现有测试和 TypeScript 类型检查通过。
3. `npm run check:config` 通过。
