# SQLite 备份保留与恢复演练记录

## 目标

验证最小备份流程能够创建多个 SQLite 副本、按确定性的命名规则保留最新两份，并从保留副本恢复虚构数据。

## 演练数据与边界

演练仅在系统临时目录中创建本次专用目录和 SQLite 文件。源库仅包含一条虚构记录：编号 `1`、标签 `backup-retention-drill`。未使用真实用户、会话、消息或业务数据。

未读取、复制、修改或删除 `ai-backend/chat.db`；未连接或修改 Render 数据库、线上服务、部署配置、环境变量、凭据或令牌。临时绝对路径没有记录在本文档中。

## 保留结果

演练先生成四份按固定时间戳命名的备份，再按名称升序选择最新两份。最终保留的备份标识为：

- `backup-2026-07-26T100000Z.db`
- `backup-2026-07-26T110000Z.db`

其他两份较早备份只在本次临时根目录中删除；整个临时根目录在验证结束后清理。

## 恢复验证

从最新保留副本创建独立恢复副本，并以只读 SQLite 连接查询。查询结果为编号 `1`、标签 `backup-retention-drill`，同时满足“只保留两份”和“恢复副本可读取预期记录”两个成功条件。

## 限制与后续

本次只验证了本地临时 SQLite 文件的命名、保留和最小恢复链路。时间戳命名不等于存在自动调度器，保留两份也不能单独定义可接受的数据丢失窗口。它不代表 Render 托管数据库已经具备备份、保留或恢复能力；这些能力仍需要根据实际套餐与平台流程在隔离环境中单独核对和演练。
