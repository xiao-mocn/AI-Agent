# 备份失败响应与恢复运行手册

## 适用范围与安全边界

本手册用于处理备份任务失败或最后一次成功备份超过 RPO 的情况。响应过程只读取调度记录、备份元数据和经批准的非敏感验证结果，不在文档、日志或工单中记录连接信息、密码、密钥或真实业务数据。

恢复必须先进入隔离目标，禁止直接覆盖、删除或修改生产数据库。生产切换属于独立的高风险操作，只有在隔离恢复验证通过、影响范围明确且取得变更审批后才能另行执行。

## 角色与责任

- **主响应人**：确认告警、收集证据、计算备份新鲜度并协调隔离恢复。
- **恢复执行人**：按平台支持的流程把已验证备份恢复到隔离目标，不操作生产目标。
- **审批人**：审查验证证据与业务影响，决定是否进入生产切换流程。
- **记录人**：保存时间线、决策、验证结果和未执行动作，不保存敏感值。

同一人可以在小型项目中承担多个角色，但生产切换审批不能仅由执行人自行确认。

## 触发条件与严重程度

满足以下任一条件时进入本手册：

1. 备份任务返回非零退出码，并产生结构化 `backup.failed` 事件。
2. 当前时间减去最后一次成功备份时间大于约定 RPO，并产生 `backup.stale` 事件。
3. 调度器没有按预期产生成功或失败记录，无法证明备份任务仍在运行。

单次失败需要记录和排查；超过 RPO 或无法确认最后成功时间时，应立即升级为数据保护风险。

## 必需证据

响应开始后记录以下非敏感信息：

- 告警时间、事件类型、稳定错误码和任务标识。
- 最后一次成功备份的时间、备份标识、完整性状态和保留位置类别。
- 当前备份年龄、约定 RPO，以及是否已经超过目标。
- 调度器最近执行记录和已批准备份目录中的元数据。
- 响应人、关键决策时间、隔离恢复结果和审批结论。

证据入口使用环境约定的占位符表示，例如 `<SCHEDULER_RUN_HISTORY>`、`<BACKUP_CATALOG>` 和 `<INCIDENT_RECORD>`；本手册不固化真实地址或访问值。

## 响应与恢复步骤

1. **确认告警**：记录事件类型、退出码、错误码和发现时间，确认事件不含敏感值。
2. **核对新鲜度**：从 `<SCHEDULER_RUN_HISTORY>` 与 `<BACKUP_CATALOG>` 找到最后一次成功备份，计算其距当前时间的分钟数，并与 RPO 比较。
3. **判断停止条件**：如果最后成功备份无法确认、备份完整性未知、隔离目标未获准、操作权限不清楚，或流程可能触碰生产数据，立即停止并升级，不尝试猜测性恢复。
4. **选择恢复点**：选择在故障前完成、元数据完整且符合恢复目标的 `<VERIFIED_BACKUP_ID>`，记录选择理由和可能的数据丢失窗口。
5. **准备隔离目标**：使用经过批准的 `<ISOLATED_RESTORE_TARGET>`。确认它与生产数据库、生产网络入口和生产写入链路分离。
6. **执行隔离恢复**：依据数据库或托管平台的官方恢复流程操作，仅把选定备份恢复到隔离目标；不得把示例占位符当作可直接执行的生产命令。
7. **只读验证**：使用只读账户检查数据库能否打开、预期 Schema 是否存在、约定的非敏感哨兵记录是否可查询，以及关键表数量是否落在预期范围。禁止通过导出真实数据来证明恢复成功。
8. **形成决策**：汇总恢复点、数据丢失窗口、验证结果、未解决风险和业务影响。验证失败则选择其他已验证备份或升级，不得继续生产切换。
9. **审批生产动作**：只有审批人确认隔离恢复证据满足要求后，才能建立单独的生产切换变更；本手册本身不授权覆盖、删除或切换生产数据库。
10. **关闭与复盘**：记录恢复耗时、最终状态、后续改进项和证据位置，确认临时隔离资源由获授权人员按约定处理。

## 只读验证清单

- 隔离目标可建立只读连接，数据库版本与预期兼容。
- 必需 Schema、表和索引存在，没有运行写入型迁移。
- 约定的非敏感哨兵记录可以查询，字段值与预期一致。
- 关键表数量或摘要落在事先定义的合理范围内。
- 验证输出只保留通过/失败、摘要和时间，不包含真实记录内容。

## 升级与结束条件

以下情况必须升级：已经超过 RPO、没有可验证备份、隔离恢复失败、发现备份损坏、权限或责任边界不明确，或需要任何生产写入、覆盖、删除与切换动作。

只有在告警原因明确、隔离恢复结果可复核、后续风险和责任人已记录时，才能结束响应。一次成功重试不会自动关闭已经发生的 RPO 超限，仍需记录实际暴露窗口和改进措施。
