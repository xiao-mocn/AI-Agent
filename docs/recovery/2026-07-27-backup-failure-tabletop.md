# 备份失败与恢复桌面演练记录

## 演练目标

使用固定的虚构备份事件，验证团队能识别备份任务失败和 RPO 超限，并按 [备份失败响应与恢复运行手册](./backup-failure-and-restore-runbook.md) 完成确认、升级、隔离恢复规划、只读验证规划和证据留存。本次是桌面走读，不执行数据库恢复、生产切换或任何线上操作。

## 固定输入与命令结果

成功模拟产生 `backup.completed`、`status=succeeded`，退出码为 `0`。失败模拟产生 `backup.failed`、`status=failed`、`errorCode=DESTINATION_UNAVAILABLE`，退出码为 `1`。

过旧检测使用以下固定输入：

- 最后成功时间：`2026-07-27T08:00:00.000Z`
- 判断时间：`2026-07-27T09:35:00.000Z`
- 备份年龄：`95` 分钟
- RPO：`60` 分钟
- 事件：`backup.stale`
- 退出码：`1`

结论：备份年龄已经超过 RPO `35` 分钟，不能只等待下一次调度重试，必须进入人工响应并记录数据保护风险。

## 响应走读

1. **确认与分工**：主响应人接收 `backup.stale` 告警，记录固定输入、失败事件和发现时间；记录人开始维护时间线；恢复执行人与审批人进入待命状态。
2. **查找证据**：主响应人应从 `<SCHEDULER_RUN_HISTORY>` 核对最近执行状态，并从 `<BACKUP_CATALOG>` 查找故障前最后一个完成且完整性已验证的备份。桌面演练不访问真实入口，只确认需要的字段和判断方法。
3. **选择恢复点**：候选恢复点记为 `<VERIFIED_BACKUP_ID>`。选择依据必须包含完成时间、完整性状态和预计数据丢失窗口；若任一项不确定，则停止并升级。
4. **选择隔离目标**：恢复目标记为 `<ISOLATED_RESTORE_TARGET>`，必须与生产写入链路分离并经过授权。没有合格隔离目标时不得尝试恢复，更不得直接使用生产数据库。
5. **规划只读验证**：恢复后先确认数据库可只读打开，再检查预期 Schema、表和索引，查询约定的非敏感哨兵记录，并核对关键表数量摘要。任何验证失败都应回到恢复点选择或升级步骤。
6. **升级与审批**：由于样例已经超过 RPO，主响应人立即向审批人报告暴露窗口、候选恢复点和未解决风险。即使隔离验证通过，生产切换仍需建立单独变更并取得明确审批。
7. **结束条件**：只有根因、备份新鲜度、隔离验证结果、风险、责任人与后续行动均有非敏感记录时，桌面响应才可关闭。

## 预期证据清单

- 可解析的成功、失败和过旧事件，以及对应退出码 `0/1/1`。
- 最后成功备份时间、备份年龄、RPO 与超限分钟数。
- 调度历史和备份目录的证据入口占位符。
- 恢复点选择理由、隔离目标批准状态与停止条件。
- 只读验证项目及每项通过或失败的摘要。
- 升级时间、审批结论、生产动作是否另行授权。

## 未执行的生产动作与安全边界

本次没有读取环境变量、连接数据库或线上服务，也没有读取真实日志、凭据和业务数据。没有创建、覆盖、删除或切换任何生产资源，没有运行写入型查询，没有把占位符替换为真实访问值。

## 限制与后续

桌面演练证明了告警解释和响应顺序可被复核，但没有证明真实平台备份可用，也没有测量实际恢复耗时。后续需要在获批准的隔离环境中使用平台支持的备份完成技术恢复演练，并对各阶段计时，以验证 RTO。
